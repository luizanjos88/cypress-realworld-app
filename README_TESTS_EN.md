# Test Documentation - Cypress Real World App (Focus on atividadesRWA)

This document provides an overview of the automated testing architecture of the Cypress Real World App project, with a special focus on the tests located in the `atividadesRWA` folder, as well as a brief overview of the API testing structure.

## Testing Project Structure

The project's test suite uses Cypress and follows the Page Object Model pattern to make the code more readable and maintainable. The main directory structure related to testing is:

```text
cypress/
├── fixtures/          # Static data used across tests
├── pages/             # Page Object classes (e.g., loginPage.ts, cadastroPage.ts)
├── support/           # Custom Cypress commands and support configuration
└── tests/             # Test spec files
    ├── api/           # Tests focused exclusively on API endpoints (e.g., api-users.spec.ts)
    ├── atividadesRWA/ # Core user flow tests (Focus of this document)
    ├── demo/          # Demonstration tests
    └── ui/            # General UI tests
```

## API Tests (`cypress/tests/api`)

API tests directly validate the application's backend without rendering the graphical interface. These tests ensure that the API routes (such as transactions, notifications, comments, users, etc.) respond with the correct status codes (e.g., 200 OK, 400 Bad Request) and handle data as expected, while also securing the endpoints.

## `atividadesRWA` Tests

The `atividadesRWA` folder contains End-to-End (E2E) tests focusing on the application's critical user journeys. These tests interact with the user interface, validating the application's behavior from the frontend all the way down to the API integration. The scenarios are split into 4 main files:

### 1. `cadastro.spec.ts` (User Registration)
Tests the account creation process using dynamic mock data generated by utility libraries (like Faker).
- **Success Scenario:** Verifies that a new user can be registered by properly filling out all mandatory fields (First Name, Last Name, Username, Password, and Password Confirmation).
- **Failure Scenario:** Attempts to register a new user with missing information, validating that the proper validation error messages are displayed on the screen.

### 2. `login.spec.ts` (Authentication)
Ensures that access to the platform works as expected.
- **Success Scenario:** Logs in using a valid, existing user account (e.g., `Heath93`) and verifies successful access to the application.
- **Failure Scenario:** Attempts to log in using invalid or incorrect credentials, ensuring the system displays the appropriate error alert ("Username or password is invalid").

### 3. `newTransactions.spec.ts` (New Transactions)
Covers the user flows for sending money and making payments.
- **With Sufficient Balance:** The user logs in and successfully sends a valid payment amount.
- **With Insufficient Balance:** Simulates a transaction where the user attempts to send an amount that exceeds their current account balance. The test validates that the system blocks the transaction and displays a visible error alert on the interface.

### 4. `transactionsVerification.spec.ts` (Transaction Verification)
Checks the transaction history and account movements.
- **Successful History Check:** Logs into an account with an existing transaction history and validates that the transactions are correctly listed.
- **Empty History Check:** Creates a completely new user account, registers a new bank account (using the Faker and Chance libraries for mock data), and verifies that the system accurately indicates the user has no prior transactions.

## How to Run the Tests

To run the tests locally, ensure both the application and the backend are running, then use the following commands in your terminal:

- **Interactive Mode (Cypress UI):**
  ```bash
  yarn cypress open
  # or
  npm run cypress open
  ```
- **Headless Mode (Terminal, running only the tests in this folder):**
  ```bash
  yarn cypress run --spec "cypress/tests/atividadesRWA/*.spec.ts"
  ```
